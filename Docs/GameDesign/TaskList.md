## 🔥 繰越タスク（最優先・Alpha 着手前に消化する）

6月・7月の計画から複数回持ち越しているタスク。8/15 に C-03 / C-04 を消化し、残るは浮力（C-01 / C-02）のみ。

- [ ] [Must] C-01: オブジェクトと水面の交差判定ロジックの実装 (4h) — *6月 Day期限 7/11 から3回繰越 → 第3週（〜8/22）へ*
- [ ] [Must] C-02: 沈み込み量に応じた浮力計算と挙動テスト (4h) — *6月 Day期限 7/12 から3回繰越 → 第3週（〜8/22）へ*
  - *※ C-01 / C-02 は優先度 S。レール移動中は自機が水に浮かないため見た目の変化が小さく、後回しにしてきた。**8/22 の週末に Beta フェーズへのデスコープを判断する**（当初は 8/15 判断としていたが、8/15 は C-03 / C-04 / A-02 を優先したため 1 週ずらした）。*
- [x] [Must] C-03: 障害物への波の反射処理の作り直し (4h) — *2026/08/15 完了*
  - [x] 障害物の位置＋半径を定数バッファで最大4件受け取り、影響半径内の頂点だけを処理する仕組み
  - [x] 入射方向を障害物の法線で反射させ、その位相を持つ波に置き換える
  - [x] 旧実装（Gerstner 波を influence で打ち消して独立した sin 波を足す方式）を撤去し、鏡像法へ置き換えた
    - 頂点から見た障害物表面の外向き法線 `n` を求め、`reflect()` で反射方向を出す
    - 円周上の反射点における入射波の位相を引き継ぐことで、周波数・位相・進行方向が入射波と連続する
    - 入射波は減衰させない（干渉させることで跳ね返りに見せるため）。代わりに障害物の内側だけ smoothstep で潰す
    - 反射の強さ・到達範囲は未使用だった `gObstacleCount.y / .z` へ載せたので、定数バッファのサイズは不変
  - [x] 数値検証：反射波が風上側だけに立つこと（風下の振幅 0）、Δt=0.12s の移動量 +0.219（理論値 +0.225）で岩から離れる向きに進むこと、入射波と重なって腹/節の比 5.29 倍の定在波ができることを確認
  - [x] **実機で「反射が全く見えない」ため 8/15 夜に追加修正**（下記）
    - 原因1：位相を `dot(dir,x)*freq + speed*time` と定義していたため波は `-dir` へ進む。3波すべてがカメラ（z=-50）へ向かって来ており、**反射面が岩の裏側になって隔てられていた**（岩→カメラ方向との内積が -0.37 / -0.73 / -0.50 で全部裏）
    - 原因2：減衰が `fade² × facing` と急峻で、実用的な強さが残るのは岩の際の 2〜3 頂点だけだった。そこはたいてい岩自体に隠れる
    - 原因3：`Game.json` の `waveFreq2 = 2.8`（波長 2.24）に対し頂点間隔が 1.95（1000÷512）で **1.1 頂点/波長**。振幅 0.15 のまま完全にエイリアスし、水面全体が波ではなく頂点単位のノイズになっていた。反射はこのノイズに埋もれていた
    - 原因4：`waveSteepness = 0` で横方向変位が無く、岩に波がせり上がる形が出ない（上下の揺れだけ）
    - 対処：時間項を `-speed * time` にして `dir` を実際の進行方向と一致させた／`fade²`→`smoothstep`・`facing`→`sqrt(facing)`・強さ 0.85→1.0・到達範囲 2.5→3.0R／`waveFreq2` 2.8→0.95、`waveSteepness` 0→0.35
    - 結果：反射帯の平均振幅 0.024〜0.038 → **0.062〜0.076**（最大 0.26）、かつ反射面がカメラ側を向くようになった
  - *※ 位相の符号と進行方向の関係はこのシェーダで最も間違えやすい点。`dir` は「波が進む向き」であり、時間項は負であることを前提にしている。*
- [x] [Must] C-04: シャドウマップの PCF 対応 (3h) — *2026/08/15 完了*
  - [x] デプス専用パス（2048×2048 / R32_TYPELESS）と Slope-Scale Depth Bias の簡易版
  - [x] 3×3 タップ比較の導入によるジャギー解消
    - 比較サンプラ s3（`COMPARISON_MIN_MAG_LINEAR_MIP_POINT` / `LESS_EQUAL` / Clamp）を静的サンプラに追加
    - `SampleCmpLevelZero` を 3×3 で叩き、1タップあたり 2×2 のハード比較が入るため実質 6×6 相当
    - 影が二値から連続値になったので、`lerp` の係数に「光が当たっている率」を掛ける形へ変更
    - `ShadowParams` の末尾 12byte のパディングを `shadowMapTexelSize`(float2) + `pcfRadius`(float) へ置換（サイズ 112byte のまま不変）
    - テクセルサイズは `RenderContext::UpdateShadowParams` がシャドウマップの実解像度から自動で埋めるため、シーン側は解像度を意識しない
  - [x] DXC で Object3d 系の VS/PS 11 本すべてコンパイル確認。逆アセンブルで `sampleCmpLevelZero` × 10、`SamplerComparisonState` が s3 に載ることを確認

  - *C-03 の作業中に該当箇所へ `TODO(D-01)` を残した。反射の見た目は障害物の位置と半径に直結するので、ここが固定のままだとレベルを組み替えても波が追従しない。*
- [ ] [Must] D-02: `RenderWater` が Application 層を直接 include しており、Engine から Application への逆向きの依存ができている。インターフェース経由へ切り離す (3h)
- [ ] [Should] D-03: カメラの near / far が固定値のままで、深度のリニアライズが実際のカメラ設定と合っていない (1h)
- [ ] [Must] D-04: `Scene::RemoveDeadEntities()` がランタイムハンドルを解放していなかった (0.5h) — *2026/08/15 に A-02 の確認中に発見し、その場で修正済み*
  - *`shared_ptr` を捨てるだけではモデル／メッシュ／ライトのハンドルは返らない。撃破した敵や破棄したエフェクトのぶんだけハンドルが積み上がり、シーンを抜けるまで回収されていなかった。破棄順は `OnExit` と揃えて「スクリプトへ通知 → リソース解放」とした（`HoeItem::OnDestroy` が解放済みハンドルを触るのを避けるため）。*
  - *残作業：同じパターンが他にないか横断確認する（T-33 と合わせて実施）。*
- [ ] [Must] D-05: `SpriteManager::DrawRect` / `DrawRectUV` の切り出し矩形がまったく効かなかった (0.5h) — *2026/08/15 に発見し、その場で修正済み*
  - *`UVTransform()` は常時マップした定数バッファへの直接参照で、`Draw()` はコマンドリストへ記録するだけ。描画直後に元の値へ戻していたため、GPU が読む頃には戻したあとの値になっていた。差し替えたまま抜け、全体描画の `Draw()` 側で identity へ戻す形へ変更。*
  - *あわせて「1 ハンドルは 1 フレーム 1 回まで」という制約を `RenderCommon.h` に明記した。同じハンドルを位置を変えて複数回描くと、全部が最後の状態で描かれる（スコアの桁表示で踏んだ）。*
- [ ] [Must] D-06: 水面メッシュの頂点密度が波の周波数に対して足りていない (2h) — *2026/08/15 に C-03 の調査中に判明*
  - *`Game.json` の水面は 1000×1000 を 512 分割＝頂点間隔 1.95。この密度で表現できるのは波長 4 以上（＝周波数 1.6 以下）まで。それより高い周波数を入れると振幅そのままでノイズ化する。*
  - *暫定対応として `waveFreq2` を 2.8→0.95 に下げたが、根本的には遠景まで 1000 サイズの平面を一様分割しているのが原因。**Master フェーズの T-32「水面メッシュの LOD 導入」を前倒しすべき**。カメラ近傍だけ細かくすれば、高周波の波も反射も表現できるようになる。*
  - *シェーダ側の第3波も `gWaveFreq * 2.5` で現状 2.0 頂点/波長。LOD 導入までは高周波側を上げないこと。*
