  - [x] 水面の高さを CPU 側で引くための `RC::WaterSurface`（`Engine/Common/Water/WaterSurface.h`）を新設
    - 波の変位は Water.VS.hlsl（頂点シェーダ）の中だけで計算していたため、ゲームロジック側からは水面がどこにあるか分からなかった。同じ式を CPU にも持つのが前提条件だった
    - `GetWaveDef` / `AccumulateGerstner` / `AccumulateReflection` / `insideMask` をすべて移植。**HLSL を独立に転記した参照実装と突き合わせ、誤差 1e-6（float精度）で一致することを確認**
    - Gerstner 波は頂点を横（XZ）にも動かすため、素朴に (x,z) を評価すると水面がずれる。「変位後に (x,z) に来る元の格子点」を不動点反復で逆算する。**残差は steepness 0.35 で 1 回 0.0006 / 2 回 0.000028**。既定 2 回で mm 以下
    - 時刻は `RC::GetWaterTime()` を新設して GPU と同じ値を読む。スクリプト側で時間を持ち直すとズレる
  - [x] 障害物（岩）も `RC::GetWaterObstacles()` でシェーダに渡っているものをそのまま貰う
    - 障害物は反射波を作るだけでなく「内側の波を平らに潰す」マスクも持つ。ここを省くと岩の近くで**描画は平らなのに当たり判定だけ波打つ**（実測で最大 0.31m のズレ）
  - [x] 底面〜水面の距離を物体の高さでクランプして沈み込み率（0..1）を出す。4点サンプル（前後左右）の平均を喫水基準にした（1点だと船体より短い波を拾って暴れる）
- [x] [Must] C-02: 沈み込み量に応じた浮力計算と挙動テスト (4h) — *6月 Day期限 7/12 から4回繰越／2026/08/23 完了*
  - [x] `BuoyancyScript` を新設。入力を「加速度」ではなく **密度比 `densityRatio`（物体密度 ÷ 水の密度）** にした
    - アルキメデスより 浮力加速度 = (g / densityRatio) × 沈み込み率。つり合うのは 沈み込み率 == densityRatio のときなので、`0.45` と書けば「45% 沈んで浮く」と読める。見た目から逆算できる形を優先した
    - **数値検証**：静水で 0.2 / 0.45 / 0.8 → 沈み込み率 0.200 / 0.450 / 0.800 に収束。1.0 で中性浮力、1.2 で終端速度 -0.654 m/s（理論値 a/k = -1.635/2.5 と一致）
    - 波ありでは平衡点まわりで上下する（0.45 指定で 0.33〜0.55、0.80 指定で 0.63〜0.95）。発散しない
  - [x] 水の抵抗は陰的に解く（`v /= 1 + k·dt`）。明示的な `v *= (1 - k·dt)` は k·dt > 1 で符号が反転して発散する
  - [x] **実機で「高いところから落とすと戻りが遅い」ため 8/23 夜に追加修正**（下記）
    - 原因：水の抵抗を**速度に比例（線形）だけ**でモデル化していた。線形抵抗は高速度域で弱すぎるため、着水時の速度がそのまま深さに変わる。**12m 落下で完全水没からさらに 3.94m 沈み、水面へ戻るまで 6.22 秒**。落下高さを上げるほど悪化した（20m→8.07s、40m→11.45s）
    - 実際の水の抵抗は**速度の2乗に比例**する。速く突っ込むほど急激に減速するので、高いところから落ちても深く潜らない。「高いところから落ちたらすぐ上がってくる」という直感のほうが物理的に正しかった
    - 対処1：`quadraticDrag`（2乗抵抗）を追加。**12m 落下の余分な沈み込み 3.94m→0.00m、水面復帰 6.22s→1.38s**。しかも 40m 落下でも復帰 1.52s とほぼ変わらない（落下高さへの依存が消える）
    - 対処2：密度 0.80 は「ほぼ水と同じ重さ」で、完全水没時の浮力が **2.45 m/s²（重力の1/4）**しかなかった。0.40 へ下げて浮力を 14.7 m/s² に。露出も 20%→60% になり、跳ね返りが水面から飛び出して見えるようになった
    - 対処3：密度を下げると減衰比が 0.16 まで落ちて延々跳ねるので、`linearDrag` を 2.5→5.5 に上げて減衰比 0.34（2〜3回跳ねて収まる）へ
    - 役割分担を整理：**`quadraticDrag` = 着水でどれだけ潜るか／`linearDrag` = そのあと何回跳ねるか／`densityRatio` と物体サイズ = 上下動の周期**
    - *※ 上下動の周期は T = 2π√(densityRatio × 全高 / g)。密度 0.8・直径 2.4m だと 2.78 秒で、これは物理的に「大きくて重いブイはゆっくり揺れる」が正しい。ブイらしい「ポコン」にしたいなら密度を下げるか物体を小さくする。ImGui に周期と減衰比を出したので、そこを見ながら合わせること。*
  - [x] 4点サンプルの高さ差から pitch / roll を出して姿勢を傾ける。**T-15「船」がそのまま使える**
  - [x] 着水／離水を `in_water` / `water_entered` / `water_exited` タグで通知（水しぶき・SE の接続点）
  - [x] `Game.json` に検証用の浮遊体2つ（`FloatCrate` 密度0.45・4点サンプル／`FloatBuoy` 密度0.80・1点サンプル）を配置。ギズモで喫水線とサンプル点が見える

    - 円周上の反射点における入射波の位相を引き継ぐことで、周波数・位相・進行方向が入射波と連続する
    - 入射波は減衰させない（干渉させることで跳ね返りに見せるため）。代わりに障害物の内側だけ smoothstep で潰す
    - 反射の強さ・到達範囲は未使用だった `gObstacleCount.y / .z` へ載せたので、定数バッファのサイズは不変
  - [x] 数値検証：反射波が風上側だけに立つこと（風下の振幅 0）、Δt=0.12s の移動量 +0.219（理論値 +0.225）で岩から離れる向きに進むこと、入射波と重なって腹/節の比 5.29 倍の定在波ができることを確認
  - [x] **実機で「反射が全く見えない」ため 8/15 夜に追加修正**（下記）
    - 原因1：位相を `dot(dir,x)*freq + speed*time` と定義していたため波は `-dir` へ進む。3波すべてがカメラ（z=-50）へ向かって来ており、**反射面が岩の裏側になって隔てられていた**（岩→カメラ方向との内積が -0.37 / -0.73 / -0.50 で全部裏）
    - 原因2：減衰が `fade² × facing` と急峻で、実用的な強さが残るのは岩の際の 2〜3 頂点だけだった。そこはたいてい岩自体に隠れる
    - 原因3：`Game.json` の `waveFreq2 = 2.8`（波長 2.24）に対し頂点間隔が 1.95（1000÷512）で **1.1 頂点/波長**。振幅 0.15 のまま完全にエイリアスし、水面全体が波ではなく頂点単位のノイズになっていた。反射はこのノイズに埋もれていた
    - 原因4：`waveSteepness = 0` で横方向変位が無く、岩に波がせり上がる形が出ない（上下の揺れだけ）
    - 対処：時間項を `-speed * time` にして `dir` を実際の進行方向と一致させた／`fade²`→`smoothstep`・`facing`→`sqrt(facing)`・強さ 0.85→1.0・到達範囲 2.5→3.0R／`waveFreq2` 2.8→0.95、`waveSteepness` 0→0.35
    - 結果：反射帯の平均振幅 0.024〜0.038 → **0.062〜0.076**（最大 0.26）、かつ反射面がカメラ側を向くようになった
  - *※ 位相の符号と進行方向の関係はこのシェーダで最も間違えやすい点。`dir` は「波が進む向き」であり、時間項は負であることを前提にしている。*
- [x] [Must] C-04: シャドウマップの PCF 対応 (3h) — *2026/08/15 完了*
  - [x] デプス専用パス（2048×2048 / R32_TYPELESS）と Slope-Scale Depth Bias の簡易版
  - [x] 3×3 タップ比較の導入によるジャギー解消
    - 比較サンプラ s3（`COMPARISON_MIN_MAG_LINEAR_MIP_POINT` / `LESS_EQUAL` / Clamp）を静的サンプラに追加
    - `SampleCmpLevelZero` を 3×3 で叩き、1タップあたり 2×2 のハード比較が入るため実質 6×6 相当
    - 影が二値から連続値になったので、`lerp` の係数に「光が当たっている率」を掛ける形へ変更
    - `ShadowParams` の末尾 12byte のパディングを `shadowMapTexelSize`(float2) + `pcfRadius`(float) へ置換（サイズ 112byte のまま不変）
    - テクセルサイズは `RenderContext::UpdateShadowParams` がシャドウマップの実解像度から自動で埋めるため、シーン側は解像度を意識しない
  - [x] DXC で Object3d 系の VS/PS 11 本すべてコンパイル確認。逆アセンブルで `sampleCmpLevelZero` × 10、`SamplerComparisonState` が s3 に載ることを確認
