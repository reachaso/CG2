■今週の実績（完了・進行中・未着手）：

・【完了】先週ぶんのビルド確認とコミット — commit 6469548「波と影の改良」として確定させた。変更20ファイル＋新規2ファイル（GameSession / SceneFlowUI）で、シーンの一周も実機で通ることを確認した

・【完了】浮力シミュレーション（C-01 / C-02、5回目の繰越を回避）— **デスコープせず実装するという判断に変更した**。理由は2点。① 前提として必要になる「CPU 側で水面の高さを引く仕組み」が、船（T-15）・水中の揺れ（T-21）・着水演出・水しぶきのすべての土台になる ② 「レール移動中の自機が浮かないので見た目に効かない」という当初の懸念は、浮かせる対象を自機から船や浮遊物へ替えれば解消する。実際に T-15 の船体を波に乗せる部分はそのまま流用できる形になった

・【完了】水面高さの CPU 版 `RC::WaterSurface` の新設（計画外・C-01 の前提）— 波の変位は頂点シェーダの中だけで計算していたため、ゲームロジック側からは水面がどこにあるか分からなかった。Gerstner 波の3成分・障害物による反射波・障害物内側の平坦化マスクをすべて CPU へ移植した。**HLSL を独立に転記した参照実装と突き合わせ、誤差 1e-6（float精度）で一致することを確認した**。Gerstner 波は頂点を横方向にも動かすので、素朴に座標を入れると水面がずれる点は不動点反復で逆算しており、実測の残差は 1 回で 0.0006、2 回で 0.000028 まで落ちる。時刻もシェーダと同じ値を読むようにしたので、見た目の水面と当たり判定の水面が食い違わない

・【完了】浮力の入力を「密度比」にした設計 — 加速度を直接持たせるのではなく、物体密度 ÷ 水の密度を入力にした。アルキメデスの原理より浮力加速度は (g ÷ 密度比) × 沈み込み率になるので、つり合うのは沈み込み率が密度比と一致したとき。つまり 0.45 と書けば「45% 沈んで浮く」と読める。静水での検証では密度比 0.2 / 0.45 / 0.8 に対して沈み込み率 0.200 / 0.450 / 0.800 に収束し、1.0 で中性浮力、1.2 では終端速度 -0.654 m/s（理論値 a÷k = -1.635÷2.5 と一致）となった

・【完了】ステージのルート分岐システムの基盤構築（T-20）— ウェイポイントに分岐リストを持たせ、到達時に先頭から判定して最初に成立したものへ飛ぶ形にした。条件は無条件・タグ一致・タグ以上・キー押下・確率の5種。**パスを複数本持つのではなく1本の配列に閉じた**のは、既存のシリアライズ形式を壊さずに済み、分岐先も合流先も同じ index 空間なので合流が特別扱いにならず、エディタ上でも1つのリストを見れば全ルートが把握できるため。実データも入れて、Game シーンで右キーを押しながら通過すると水上ルートへ分かれ、共通のゴールで合流することを確認した。ウェーブ戦闘（A-03）から使う一時停止と再開の口も先に公開しておいた

・【完了】T-20 の作業中に「終点」の概念が必要だと分かり追加 — 分岐で index が飛ぶようになると「配列の末尾＝終点」が成り立たなくなる。迂回ルートを後ろの index に置いて本線へ合流させると、合流先の次の index が迂回ルートの起点になるため**永久に周回してしまう**。実際に自分で置いたデータで踏んだので、終点フラグを足して解消した

・【完了】レベルローダーの LIGHT / CAMERA 対応（A-05）— 平行光源・点光源・スポット・エリアの4種とカメラを解釈するようにした。ハンドル生成は既存の初期化処理が面倒を見てくれるので、対応コンポーネントを付けるだけで済んだ。ライトの向きは JSON に指定が無ければ回転から導出し、その式はシャドウパスが向きから回転を求めている式のちょうど逆変換にしてある。Blender 固有の値（energy、円錐の全開き角、エリアの辺の長さ、clip_start / clip_end）も吸収した

・【完了】A-05 の作業中に回転の単位の食い違いを発見・解消 — エンジン全体で回転はラジアンなのに、サンプルレベルのデータは度数法（45.0 や 106.936）で書かれていた。そのまま読むと数十ラジアンずれる。ファイル単位で切り替えるフラグを設け、既定はラジアン（＝従来動作、Blender の出力そのまま）とした。実際にロードして値を出力し、向きの正規化・角度変換・度数変換・子要素の再帰がすべて期待どおりであることを確認した

・【完了】既存不具合の発見と修正4件（D-07 〜 D-10）— ① 名前でエンティティを引く関数がスクリプトから呼べない位置にあった（リポジトリ全体で呼び出し元が1つも無かったため気づかれていなかった）② シーン保存がレベルデータ由来のエンティティも書き出しており、保存のたびに複製が増える状態だった ③ スクリプトが他コンポーネントの設定値を書き換えるとシリアライズ経由でシーンデータに焼き付いてしまう問題。当初は重力の二重適用を防ぐために Rigidbody の設定を書き換えていたが、一度保存するとスクリプトを外しても無重力の物体が残る。**スクリプトは他コンポーネントの設定値を書き換えず、毎フレーム相手の状態を見て自分の振る舞いを変える**という方針に改めた ④ `std::max` / `std::min` は Windows.h のマクロと衝突するため括弧で囲む必要がある（後述）

・【完了】ビルドエラーの解消 — Debug ビルドが C2589 で6件失敗した。原因は `std::max` / `std::min` と Windows.h のマクロ衝突で、シーン関連のヘッダ経由で Windows.h が入ると `max(` がマクロ展開されて `std::((a)>(b)?…)` になる。既存のシーン処理が以前から括弧付きで書いていたので、それを慣例として統一した。ヘッダ側はインクルード順に依存しないよう同じ形にした

・【完了】浮力の挙動修正（実機確認からの手戻り）— 高いところから落としたときに戻りが遅く、**自分の直感（高いところから落ちてもすぐ上がってくるはず）のほうが物理的に正しかった**。原因は水の抵抗を速度に比例する線形項だけでモデル化していたことで、線形抵抗は高速度域で弱すぎるため着水時の速度がそのまま深さに変わっていた。数値で見ると 12m 落下で完全水没からさらに 3.94m 沈み、水面へ戻るまで 6.22 秒かかり、落下高さを上げるほど悪化していた（20m で 8.07 秒、40m で 11.45 秒）。実際の水の抵抗は速度の2乗に比例するので、速く突っ込むほど急激に減速して深く潜らないのが正しい。2乗抵抗を足したところ **12m 落下の余分な沈み込みが 0.00m、水面復帰が 1.38 秒**になり、さらに 40m 落下でも復帰 1.52 秒とほぼ変わらなくなった（落下高さへの依存が消えた）

・【完了】上記に伴うパラメータの整理 — 密度比 0.80 は「ほぼ水と同じ重さ」で、完全水没時の浮力が 2.45 m/s²（重力の4分の1）しかなく、しかも水面上に出るのが 20% だけで「戻ってきた」ことが見えなかった。0.40 に下げて浮力 14.7 m/s²、露出 60% にしたところ、跳ね返りで水面から飛び出すようになった。下げると跳ねすぎるので線形抵抗を上げ、減衰比 0.34（2〜3回跳ねて収まる）に合わせた。**2乗抵抗＝着水でどれだけ潜るか、線形抵抗＝そのあと何回跳ねるか、密度比と物体サイズ＝上下動の周期**という役割分担に整理し、周期・減衰比・水没時の浮力・平衡時の露出を ImGui に表示して感覚で追い込めるようにした
