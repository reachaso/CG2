■今週の実績（完了・進行中・未着手）：

・【完了】シャドウマップの PCF 対応（C-04、繰越3週目でようやく消化）— 単点比較の `Sample` を 3×3 の `SampleCmpLevelZero` へ置き換えた。比較サンプラを静的サンプラに追加し、1タップあたりハードウェアで 2×2 の比較が入るため実質 6×6 相当のフィルタになっている。テクセルサイズと PCF 半径は `ShadowParams` の末尾に余っていたパディング領域へ載せたので、定数バッファのサイズは 112 byte のまま変えずに済んだ。テクセルサイズは実解像度から自動で埋まるため、シーン側が解像度を知る必要はない。影が二値から「光の当たっている率 0〜1」の連続値になったので、シャドウマップ外周では別途フェードを掛けて境界が唐突に出ないようにした

・【完了】障害物への波の反射処理（C-03、繰越3週目で消化）— 旧実装は入射波と無関係な同心円リップルを足したうえで元の波を最大80%打ち消しており、位相も進行方向も引き継がれないため跳ね返りに見えていなかった。これを鏡像法（image-source method）へ全面的に置き換えた。頂点から見た障害物表面の外向き法線を求め、風上側を向いている場合だけ反射波を作り、円周上の反射点における入射波の位相をそのまま引き継ぐ。こうすることで周波数・位相・進行方向が入射波と連続する。入射波は減衰させず、干渉させることで跳ね返りに見せている。反射の強さと到達範囲は未使用だった定数バッファの空きフィールドへ載せたので、こちらもレイアウトは不変

・【完了】上記 C-03 の実機確認と追加修正 — 数値検証は通っていたのに実機では反射が全く見えず、録画を解析して原因を4つ特定した。① 位相の定義上、波が実際に進む向きが指定方向と逆になっており、3波すべてがカメラ側へ向かってきていたため反射面が岩の裏に隠れていた ② 減衰カーブが急峻すぎて、実用的な強さが残るのが岩の際の2〜3頂点だけだった（そこは岩自体に隠れる）③ 水面の周波数設定に対して頂点密度が 1.1頂点/波長 しかなく、波がノイズ化して反射がそこに埋もれていた ④ 横方向変位が 0 で、岩に波がせり上がる形が出ていなかった。①②はシェーダ側、③④はシーン設定側を修正した

・【完了】コアゲームループの結合（A-02、Prototype 第6週からの繰越）— 遷移判定そのものは既存のものがあり、足りていなかったのは「シーンをまたいだ結果の受け渡し」と「画面表示」だった。スコア・残HP・経過時間・クリア判定・評価ランク・プレイ回数を保持する `GameSession` を新設し、Game シーンの開始時にリセット、プレイ中は毎フレーム書き込む形にした。あわせて Title / Result / GameOver の HUD を担う `SceneFlowUI` を作り、3つのシーン JSON へ配置した。Result はスコアの数字表示と、色付きバーの本数による評価ランク表示に対応している

・【完了】既存不具合の発見と修正2件（D-04 / D-05）— ① シーンの死亡エンティティ回収処理が `shared_ptr` を捨てるだけで、モデル・メッシュ・ライトのランタイムハンドルを解放していなかった。撃破した敵やエフェクトのぶんだけハンドルが積み上がり、シーンを抜けるまで回収されていなかったため、破棄順をスクリプト通知 → リソース解放の順に整えて修正した ② スプライトの切り出し矩形指定がまったく効いていなかった。定数バッファへ直接書いたあと描画直後に元へ戻していたため、GPU が読む頃には戻したあとの値になっていたのが原因。あわせて「1つのスプライトハンドルは1フレームに1回しか描画できない」という制約をヘッダに明記した（スコアの桁表示で実際に踏んだため、桁ごとに別ハンドルを確保する形にした）

・【進行中】波の反射の最終確認（進捗 90%）— 上記の追加修正までは入れたが、直した状態での実機録画による再確認がまだ済んでいない。狙いどおり岩から波が離れていく画になっているかを見て、問題なければクローズする

・【進行中】水面メッシュの頂点密度不足への対応（D-06、進捗 20%）— 暫定対応として波の周波数を下げてエイリアスは解消したが、根本原因は遠景まで一様分割している水面メッシュそのものにある。Master フェーズに置いていた「水面メッシュの LOD 導入」を前倒しすべきと判断し、技術的負債として登録した。LOD が入るまでは高周波側の波を上げられない
